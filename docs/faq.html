引擎相关

Q1：you-get 和 yt-dlp 应该选哪个？

you-get 对国内视频站（B 站、优酷、腾讯、爱奇艺等）支持较好，配置简单； yt-dlp 支持的站点数量更多、更新更活跃，对 YouTube 及国外站点支持更强，且支持字幕、播放列表等高级功能。 两者可同时安装，随时在工具栏切换。

Q2：提示「引擎不可用」怎么办？

请将对应的可执行文件（Windows 下为 you-get.exe、yt-dlp.exe） 放入程序目录下的 engines 文件夹，或安装到系统 PATH 中。 推荐使用内置方式，免安装、免配置。

Q3：yt-dlp 下载高清视频时提示缺少 FFmpeg？

部分高画质视频的音视频是分离的，需要 FFmpeg 进行合并。 请下载 FFmpeg 并将其 bin 目录加入系统 PATH，或放在 engines 文件夹下。

Cookie 相关

Q4：为什么有些链接下载失败，提示需要 Cookie？

部分平台对未登录用户隐藏高画质或限制访问。请在「设置 → Cookie 管理」中为对应平台添加 Cookie。 可以使用内置的「一键导出」功能，自动从浏览器提取当前登录状态的 Cookie。

Q5：Cookie 会过期吗？

会。多数平台的登录凭证有有效期，过期后需要重新导出。 若下载突然开始失败并出现 403 等状态码，建议先更新对应平台的 Cookie。

Q6：我的 Cookie 会被上传吗？

不会。Cookie 仅保存在您本机的用户目录下，程序运行过程中不会将其发送到任何第三方服务器， 仅作为参数传递给本机的下载引擎用于访问目标平台。

自定义请求头

Q7：什么情况下需要自定义请求头？

某些平台在服务端校验请求来源（Referer）或客户端标识（User-Agent）时， 只带 Cookie 可能仍被拒绝。这时可以在「设置 → 通用 → 自定义请求头」中补充。

Q8：请求头是全局生效还是只对特定站点生效？

程序会自动判断：
• 值中含域名的请求头（如 Referer: https://www.example.com/）只对匹配该域名的链接生效；
• 值中不含域名的请求头（如 User-Agent、Accept）对所有链接全局生效。
每行一条，格式为 Key: Value。

日志与输出

Q9：日志文件保存在哪里？

日志按日期分目录存储，路径为：<日志目录>/YYYYMMDD/download.log。 日志目录可在「设置 → 通用」中修改，并支持「移动」功能将历史日志整体迁移到新位置。

Q10：日志区内容太多，如何清空？

点击日志区右上角的「🗑 清空日志」按钮即可清空界面显示。 已写入磁盘的历史日志不受影响，仍保留在对应的日期文件夹中。

Q11：下载完成后如何快速找到文件？

下载完成弹窗中提供「打开下载目录」按钮，可直接打开目标文件夹。 日志区也会列出本次成功下载的完整文件路径。

故障排查

Q12：点击「开始下载」后没有任何反应？

请依次检查：
1. 下载目录是否存在且可写；
2. 当前引擎是否可用（工具栏左侧状态标签是否为绿色）；
3. URL 列表是否为空或格式错误；
4. 查看日志区是否有报错信息。

Q13：下载到一半失败，部分任务未完成？

多数是目标平台的网络波动或风控触发。可等待几分钟后重试； 若某条链接反复失败，请在日志区查看具体报错内容，必要时更新 Cookie 或更换引擎。

Q14：并发数设置多少合适？

建议 3~5。并发数过高容易触发平台风控导致失败率上升， 也会占用较多系统资源。若下载频繁失败，可先将并发数降为 1 逐个排查。
